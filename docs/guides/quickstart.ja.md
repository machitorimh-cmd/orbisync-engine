# クイックスタート

**日本語** | [English](quickstart.en.md)

まずはこのPCで、エンジンの起動から実通信まで試します。PostgreSQLは配布版に同梱されているため、DBの作成、接続URLの入力、Rust・Node.js・Dockerのインストールは不要です。

## 1. ダウンロードして展開する

[v0.1.0-preview.3の配布ページ](https://github.com/machitorimh-cmd/orbisync-engine/releases/tag/v0.1.0-preview.3)から、OSに合うファイルをダウンロードします。GitHubが自動生成する「Source code」ではなく、次のアーカイブを選んでください。

| OS | ファイル |
|---|---|
| Windows x64 | `orbisync-v0.1.0-preview.3-windows-x86_64.zip` |
| Linux x86_64（glibc 2.35以降） | `orbisync-v0.1.0-preview.3-linux-x86_64.tar.gz` |

書き込み可能な専用フォルダに、アーカイブ全体を展開します。実行ファイルと同梱の `runtime/` は一緒に置いてください。

## 2. ランチャーを起動する

Windowsでは、展開したフォルダの **`start-web-admin.cmd`** を開きます。管理者権限は不要です。

Linuxでは、一般ユーザーで次を実行します。

```sh
tar -xzf orbisync-v0.1.0-preview.3-linux-x86_64.tar.gz
cd orbisync-v0.1.0-preview.3-linux-x86_64
./start-web-admin.sh
```

ブラウザに管理画面が開きます。開かない場合は端末に表示されたプライベートURLを使います。ログをファイルへ出力した場合は、展開先の `.orbisync-admin/launch-url.txt` にURLが保存されます。

## 3. 「このPCで試す」を押す

DBの準備、初期設定、エンジン起動が順に進み、管理画面へ自動でログインします。初回だけ表示される管理者パスワードを安全に保存してください。

接続テストの **HTTP・WebSocket・入室・初期同期** がすべて成功すれば、起動確認は完了です。テスト用のWorldとInstanceがローカル試用環境に作られます。SDKの生成やサンプルアプリのビルドは必要ありません。

## 停止・再開する

- **エンジンとローカルDBを停止**：DBとエンジンを停止します。データと設定は残ります。
- **エンジンを起動**：保存済みの環境を起動します。
- **エンジンを再起動**：DBとエンジンを再起動し、保存した設定を反映します。
- ランチャーを終了する場合は、起動した端末で **Ctrl+C** を押します。

次回は同じフォルダのランチャーを開き、**ローカル試用を再開**を選びます。DBを作り直す必要はありません。データと認証情報は `.orbisync-admin/` に保存されるため、このフォルダを削除したり共有したりしないでください。

## うまく起動できないとき

| 状況 | 操作 |
|---|---|
| 管理画面が開かない | 今回の起動で表示されたURLを開きます。管理ポートが使用中なら別の空きポートが選ばれます。 |
| DB・エンジンのポートが使用中 | 診断画面で案内されるポート変更を選びます。 |
| 準備の途中で失敗した | **ローカル起動を再試行**を選びます。保存先の権限や空き容量も確認します。 |
| 接続テストが失敗した | 診断内容を確認し、**接続テストを再試行**します。必要ならエンジンを再起動します。 |

## ログインなしでアプリから参加する

1. 管理画面で参加先のWorldとInstanceを作成し、Instanceを起動します。
2. **設定 → ゲスト参加**で**ゲスト参加を許可する**をONにし、参加を許可するWorldにチェックします。
3. **検証して再起動用に保存**を押し、**エンジンを再起動**します。初回は参加に必要な権限だけを持つGuestロールも準備します。
4. アプリにはエンジンの接続先URLとInstance IDを設定し、ゲスト認証してJoinします。すでに接続していたアプリは退出して再度Joinしてください。

ゲスト認証の成功と入室の許可は別です。`NOT_AUTHORIZED` で入室できない場合は、対象Instanceが属するWorldを許可したか確認します。World IDとInstance IDは別の値です。変更は再起動後に新しく認証するゲストから適用され、ゲスト参加をOFFにしても通常の管理者ログインは維持されます。

## 次にできること

管理画面でユーザー・World・Instanceを管理できます。自分のアプリを接続する場合は[フロントエンド接続ガイド](frontend-integration.md)へ進んでください。描画やアプリの画面は、接続するアプリ側で作ります。

ローカル試用はこのPC内の通信に限定される開発用プレビューです。外部DB、既存環境、画面のないサーバー、保存先やバックアップの詳細は[配布版の利用ガイド](../../deploy/distribution/README.ja.md)と[Web管理ガイド](../../apps/admin-web/README.md)を参照してください。
